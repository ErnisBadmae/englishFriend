Функциональные требования

Каналы доступа: Telegram-бот/мини-приложение, кроссплатформенное мобильное приложение (iOS/Android) и веб-клиент. Все модули ниже должны работать одинаково независимо от выбранного канала.
1.1. Модуль пользовательского профиля

Требования:
Регистрация и онбординг.
Сбор интересов (минимум 3, текстовый ввод, например "IT, кино, спорт").
Самооценка уровня английского (beginner, intermediate, advanced).
вообще под вопросом этот момент! может пусть ии сам собирает в ходе общения

Хранение истории диалогов (последние 10-15 реплик в JSON для контекста).
Базовая система прогресса: отслеживать сессии и давать простые достижения (типа "Ты поговорил 3 раза на этой неделе!").

Входные данные:
Интересы: строка.
Уровень: выбор из опций.
Обновление профиля: пользователь может изменить данные в любой момент через команду /profile или через экран профиля в мобильном/веб-клиенте.

1.2. Модуль голосового взаимодействия
Требования:
Прием голосовых сообщений с запуском звонка из Telegram, мобильного приложения или веб-клиента.
Преобразование речи в текст (STT).
Генерация ответа на английском.
Преобразование текста в речь (TTS).
Обработка ошибок: если STT не сработал - попросить текстом или повторить.
Fallback: поддержка текстового ввода, если голос неудобен.

Качество:
Время ответа ≤ 10 секунд.
Точность распознавания ≥ 85-90% (тестировать на разных акцентах).
Естественный голос (с эмоциями, если API позволяет).

Фокус на обучении: После диалога - 1-2 комментария по произношению (например, "Ты хорошо сказал 'hello', но попробуй 'th' в 'think' как 'финг'"). Мини-упражнения: иногда предлагать повторить фразу.
1.3. Модуль диалоговой системы
Требования:
Персонализированные разговоры по интересам (≥50% реплик ссылаются на профиль).
Поддержка контекста (5-10 последних сообщений).
Адаптация под уровень: простой язык для новичков, сложнее для продвинутых.
Дружелюбный тон: шутки, вопросы, поддержка.
Улучшение английского: мягко исправлять ошибки, предлагать синонимы или упражнения (например, "Повтори: 'I love coding in Python'").

Характеристики:
Использовать промпты для LLM: "Ты дружелюбный ИИ-друг, говори на английском, учитывай интересы , уровень языка пользователя. Будь любопытным и поддерживающим."
Запоминание: ссылки на прошлые разговоры (например, "В прошлый раз ты упомянул Django - как дела с проектом?").

Компоненты:

2.3. Требования к производительности

Время ответа ≤ 10 секунд.
Доступность ≥ 98%.
Резервное копирование данных еженедельно.

2.4. Безопасность
Шифрование данных в БД.
Согласие на обработку (в онбординге: "Мы храним твои диалоги для улучшения, но ты можешь удалить профиль").
Логи: без хранения голосовых файлов дольше 24 часов.

Бизнес-логика
3.1. Процесс онбординга
/start - приветствие: "Привет! Я твой English Friend. Давай познакомимся." (в мобильном/веб-клиенте это экран приветствия).
Ввод интересов: "Расскажи, чем увлекаешься? (например, IT, фильмы)"
Уровень: "Твой уровень английского? 1 - beginner, 2 - intermediate, 3 - advanced." (в мобильном/веб — выбор на экране).
Первый диалог: "Ок, начнем! Что скажешь о [интерес]?" (кнопка/CTA "Начать разговор" в приложении и на вебе).
Либо это вообще опустим, пусть ИИ агент в процессе формирует портерт пользователя

3.2. Диалоговый процесс
Пользователь шлет голос/текст.
Распознавание → текст.
Анализ: контекст + профиль.
Генерация ответа (с персонализацией и обучением).
TTS → голосовой ответ.
Обратная связь: иногда добавить "Хорошо сказал, но вот совет по произношению."

3.3. Логика персонализации
Всегда учитывать интересы в вопросах.
Адаптировать словарь под уровень.
Запоминать темы из прошлых сессий.
Усложнять gradually: после 3-5 сессий вводить новые слова.
