# Документация проекта: правила обслуживания

Last updated: 2026-07-03
Инструмент: `scripts/docs_maintenance.py` (канонический источник — репозиторий expert-agent,
версия — `python scripts/docs_maintenance.py --version`).

## Принцип

Документация — часть кода. Она должна быть **короткой**, **активной** и **убираемой**.
Если документ не помогает принять решение или выполнить задачу — он устарел.

## Правила для людей и агентов

### 1. Размер — ограничен

- **Лимит:** 300 строк на living-файл. Растёт дальше — разделяй.
- Исключение: `archive/` — лимит не применяется (audit его не проверяет).
- Превышение — `WARN` при `python scripts/docs_maintenance.py audit`.

### 2. Контекстный бюджет (токен-правило)

Tier-0 файлы — те, что агент обязан прочитать на старте каждой сессии — перечислены
в `[tool.docs-maintenance] tier0_files` (pyproject.toml). Их суммарный размер — цена
входа в проект; audit меряет её против `context_budget_lines` (KPI: ≤ 2000 строк).
Раздувается — детали уносить в tier-2 документы, а не расширять бюджет.

Читай файлы последовательно, не все сразу. Не читай `archive/`, если не нужна конкретная дата.

### 3. Tiers документов

| Tier | Когда читать | Где лежит | Пример |
|------|-------------|-----------|--------|
| **0** | Всегда (старт сессии) | Корень + `operations/` | `!DOC/README.md`, `!DOC/ARCHITECTURE.md`, `CURRENT_PRODUCT_STATE.md`, `SESSION_LOG.md` |
| **1** | При планировании | `strategy/` | roadmap, vision |
| **2** | По задаче | Подкаталоги | `architecture/*.md`, runbooks |
| **3** | Только при необходимости | `archive/`, `research/` | исторические документы |

### 4. Обновление

- Каждый living-документ несёт `Last updated: YYYY-MM-DD`; при изменении — обновляй дату.
- При устаревании — перемещай в `operations/archive/` через `git mv` (история сохраняется).
- Не создавай дубликатов: если документ дублирует существующий — расширь существующий.

### 5. Именование

- `YYYY-MM-DD` в имени = артефакт с датой (задача, исследование, расследование).
- Без даты = living-документ (архитектура, навигация, состояние).
- `archive/` — всё завершённое, проверенное, не активное.

### 6. Ссылки

- Между каталогами — относительные: `../architecture/FILE.md`.
- Внутри каталога: `FILE.md`.
- Не оставляй битых ссылок — `git mv` + правка ссылок в одном коммите.

## Автоматизация

### `python scripts/docs_maintenance.py audit`

- oversized living-файлы (>300 строк, `archive/` исключён)
- слишком глубокие каталоги (>4 уровней)
- дубликаты H1 между living-файлами
- missing `Last updated` в `README.md`
- переполнение архива (>50 файлов)
- SESSION_LOG без архивации
- контекстный бюджет tier-0 файлов

### `python scripts/docs_maintenance.py archive`

Удаляет дубликаты из SESSION_LOG.md, архивирует старые записи по ISO-неделям
(`operations/archive/SESSION_LOG_YYYY-Www.md`), оставляет последние 10 записей +
текущую неделю. **Отказывается работать с незакоммиченным SESSION_LOG** — перезапись
living-файла должна быть diff-ревьюируемой (`--force` — осознанный override).

### `python scripts/docs_maintenance.py report`

Тот же audit, но JSON — для CI и ночного раннера.

### Конфигурация

`[tool.docs-maintenance]` в `pyproject.toml` (Python 3.11+; ключи = имена ниже):

| Ключ | По умолчанию | Описание |
|------|-------------|----------|
| `doc_dir` | `!DOC` | каталог документации |
| `session_log` | `!DOC/operations/SESSION_LOG.md` | путь журнала |
| `archive_dir` | `!DOC/operations/archive` | куда архивировать |
| `keep_last` | 10 | сколько записей хранить в SESSION_LOG |
| `keep_days` | 7 | записи этой недели всегда остаются |
| `max_file_lines` | 300 | лимит строк на living-файл |
| `max_archive_files` | 50 | лимит файлов в archive/ |
| `max_nav_depth` | 4 | максимальная глубина каталогов |
| `tier0_files` | `[]` | файлы контекстного бюджета |
| `context_budget_lines` | 2000 | лимит суммы строк tier-0 |

Числовые лимиты можно переопределить env-переменными `DM_KEEP_LAST`, `DM_KEEP_DAYS`,
`DM_MAX_FILE_LINES`, `DM_MAX_ARCHIVE_FILES`, `DM_MAX_NAV_DEPTH` (работают и без pyproject).

## Шаблоны

### Living-документ

```markdown
# Название

Last updated: 2026-07-02

Короткое описание.
```

### Запись в SESSION_LOG.md

```markdown
## YYYY-MM-DD - Краткое описание задачи

**Задача:** ...
**Статус:** ✅ Завершено / 🚧 В процессе / ❌ Заблокировано
**Агент:** Claude Code / Codex
**Что сделано:** ...
**Файлы:** ...
**Проверено:** ...
**Открытый хвост:** ... (если есть)
```

Разделитель в заголовке — дефис `-` (em-dash `—` тоже парсится, но дефис — канон).

## Перенос в другой репозиторий

1. Скопировать `scripts/docs_maintenance.py` как есть (не форкать — правки только
   в каноническом источнике, потом копировать; сверка по `--version`).
2. Добавить `[tool.docs-maintenance]` в `pyproject.toml` под layout репозитория
   (или положиться на дефолты `!DOC/operations/`).
3. `python scripts/docs_maintenance.py audit` — увидеть состояние.
4. `python scripts/docs_maintenance.py archive` — почистить журнал (от чистого git-состояния).
5. Скопировать этот файл как `!DOC/DOC_GUIDELINES.md` и адаптировать tier-таблицу.
